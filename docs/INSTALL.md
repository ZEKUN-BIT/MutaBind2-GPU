# Installation

This is a source distribution of an unofficial GPU-accelerated MutaBind2 implementation. The Python CLI can be installed and tested independently; actual predictions require separately installed native tools.

## Python and external dependencies

Use Linux x86-64 and Python 3.11 or later. Clone into an ASCII path, preferably lowercase, because legacy CHARMM decks and the native build output have path restrictions:

```bash
git clone https://github.com/ZEKUN-BIT/MutaBind2-GPU.git mutabind2-gpu
cd mutabind2-gpu
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[test]'
cp config/tools.example.json config/tools.json
```

Configure these external dependencies in `config/tools.json`:

| Key | Required installation |
|---|---|
| `vmd` | VMD executable |
| `charmm` | CPU CHARMM executable, matching the source/build used below |
| `namd` | Working NAMD executable or your own wrapper; tested locally with NAMD 3.0.1 CUDA |
| `dssp` | DSSP executable (`mkdssp`) |
| `foldx` | FoldX executable; tested locally with FoldX 5 |
| `rscript` | Rscript with `randomForest` and `forestFloor` installed |
| `provean_binary` | The separate PROVEAN 1.1.5 compatibility build |
| `psiblast`, `blastdbcmd`, `cdhit` | BLAST+ and CD-HIT executables; local validation used BLAST+ 2.17.0 and CD-HIT 4.8 |
| `blast_db` | Prefix of a readable BLAST NR protein database, not a FASTA file |
| `pb_executable`, `vdw_executable` | Wrappers generated by the native build below |

Paths in the JSON are relative to the configuration file, or can be absolute. `--config /path/tools.json` and `MUTABIND2_CONFIG` select another configuration. `BLAST_DB_NR` overrides the database. The example configuration contains placeholders and cannot run a prediction until edited.

You must obtain third-party software under its applicable terms. This repository does not include proprietary binaries, CHARMM installations, NAMD containers, Conda environments or NR databases.

## PROVEAN compatibility build

The source in `toolchain/vendor/provean-1.1.5/` preserves the GPL license and has documented changes for typed sequence identifiers and modern BLAST retrieval. It remains PROVEAN 1.1.5, with unchanged scoring equations.

With `make`, a C++ compiler, `psiblast`, `blastdbcmd` and `cd-hit` on PATH:

```bash
sh toolchain/scripts/build_provean.sh
```

The default installation prefix is `toolchain/external/provean-1.1.5-modern`. An optional first argument selects another prefix. Set `MUTABIND2_PSIBLAST`, `MUTABIND2_BLASTDBCMD` and `MUTABIND2_CDHIT` to explicit companion-tool paths when needed. Update the JSON configuration to the actual installed paths.

## Native GPU and compact VDW libraries

You need an authorized CHARMM 51 source tree and an existing compatible CMake Makefiles build, including `libchmm.so`, module files and the matching CHARMM executable. You also need GNU Fortran, `patch`, a compatible NVIDIA driver and CUDA Toolkit; the local build used CUDA 13.1 / `sm_120`. CUDA architecture must match your GPU. Other CHARMM source revisions require porting and independent validation; the script deliberately refuses unrecognized hashes.

The repository contains only CUDA kernels and minimal patches. The build copies the required Fortran files from your installation to a new output directory, applies patches, verifies the resulting source checksums, compiles replacements, and links an isolated library using the existing CHARMM objects. It does not overwrite your original library.

Replace `/opt/charmm` and `sm_120` with your own paths and architecture:

```bash
python scripts/build_native.py \
  --kind pb --source /opt/charmm \
  --build /opt/charmm/build/cmake \
  --executable /opt/charmm/bin/charmm \
  --cuda /usr/local/cuda --arch sm_120 \
  --output "$PWD/native_build/pb"

python scripts/build_native.py \
  --kind vdw --source /opt/charmm \
  --build /opt/charmm/build/cmake \
  --executable /opt/charmm/bin/charmm \
  --output "$PWD/native_build/vdw"
```

Use a new, empty, lowercase ASCII output path. Add repeatable `--runtime-lib /path/to/lib` options if your CHARMM build needs extra runtime libraries. Compilation is serial, has an 8 GiB address-space allowance, and requires at least 18 GiB available host memory. Failures retain logs. Successful linking is not a substitute for numerical validation on your installation.

Set `pb_executable` to the PB output's `bin/charmm` and `vdw_executable` to the VDW output's `bin/charmm`. See [native scope and behavior](../native/README.md).

## Verification and use

```bash
python -m pytest -q
./mutabind2 doctor --scope gpu
```

The tests exercise planning, mappings and checkpoints without running native tools. `doctor` checks actual executables, R packages, database readability and GPU/backend identity. Run the 1CSE example in the main README before larger scans.

To compare CPU/GPU energies using a completed scan's saved geometries:

```bash
python scripts/compare_energy.py \
  --scan projects/1cse_scan \
  --config config/tools.json \
  --output /tmp/mutabind2_energy_check
```

An output directory must be new. The comparison checks coordinates, PB grids and energy differences; its tolerance is 10⁻⁴ kcal/mol. `--rebuilt-pb` and `--rebuilt-vdw` optionally check additional rebuilt wrappers.

For full-sequence PROVEAN, prepare a one-chain FASTA whose positions agree with the original PDB numbering:

```bash
./mutabind2 scan provean \
  --sequence /data/full_sequence.fasta --chain I \
  --mutations examples/mutations.tsv --output projects/full_provean

./mutabind2 scan run \
  --pdb examples/1cse.pdb --partner1 E --partner2 I \
  --mutations examples/mutations.tsv \
  --provean-mode full --provean-cache projects/full_provean \
  --output projects/1cse_full_sequence
```

All observed residues are checked against the supplied sequence. Numbering offsets, insertion codes and negative residue numbers require an explicit verified mapping before this workflow. Never reuse an existing cache directory after changing the database or native tools; see [known limitations](KNOWN_LIMITATIONS.md).
