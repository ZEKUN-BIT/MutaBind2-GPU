## 构建最新后端

沿用安装指南的 `--source`、`--build`、`--executable`、`--cuda`、`--arch`、`--runtime-lib` 参数：

```bash
python scripts/build_native.py --kind pb-latest \
  --source /opt/charmm --build /opt/charmm/build/cmake \
  --executable /opt/charmm/bin/charmm --cuda /usr/local/cuda --arch sm_120 \
  --output /tmp/mutabind2_pb_latest
python scripts/build_native.py --kind vdw-gpu \
  --source /opt/charmm --build /opt/charmm/build/cmake \
  --executable /opt/charmm/bin/charmm --cuda /usr/local/cuda --arch sm_120 \
  --output /tmp/mutabind2_vdw_gpu
```

输出路径必须是小写 ASCII 且没有空格。原 `pb` 与 `vdw` 构建选项仍可使用。所有原始和增量补丁有输入/输出哈希检查，完整 CHARMM 源码仍由使用者提供。更换库后需对固定几何运行 `scripts/compare_energy.py`，在新扫描的配置中选择生成的两个 `bin/charmm` 启动器。

## 使用流水线和资源等待

先通过通用扫描入口准备输入、PROVEAN 和 WT 基线，再运行扩展入口：

```bash
./mutabind2 scan run --pdb examples/1cse.pdb --partner1 E --partner2 I \
  --mutations examples/mutations.tsv --output projects/new_scan --baseline-only
python scripts/run_pipeline.py --output projects/new_scan
```

使用安装了项目依赖的 Python。新入口保留当前批次结果后才报告预取失败；只对明确的资源准入拒绝等待/重试，其他原生和数值错误仍报错。恢复需要相同代码、配置、原生库和科学协议。完成的历史扫描保留原始记录，不重写为新协议。

固定日期目录中的旧构建、部署和实验脚本也随源代码保存，用于追溯；部分脚本依赖原本机资料。跨机器构建使用上面的参数化入口，通用流水线使用 `scripts/run_pipeline.py`。不能把历史脚本的绝对路径直接用于其他安装。

安装目录包含大写或空格时，默认原生暂存区改用 `~/.cache/mutabind2/workspaces`；显式 `--workspace-root` 和 `MUTABIND2_WORKSPACE_ROOT` 仍优先，并继续校验小写 ASCII 路径。

完整结果及校验方法见 [results/README.md](../results/README.md)。
