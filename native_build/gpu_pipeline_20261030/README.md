# VDW 构表 / 筛选与 PB MSTEP 的 GPU 优化

本目录包含独立的本地 CHARMM 扩展。计算流程与科学输入沿用前一版本：
原随机种子、网格、容差、双精度距离计算和单精度网格均保留。原生产包、
库及流水线文件没有被覆盖；经过验证的后端通过新路径和新协议接入。

## 实现

- `vdw/pairs_cuda.cu`、`vdw/build.py`：对覆盖全体系的截断半径，在严格检查
  无固定原子、特殊排除、周期边界、扰动、多副本、Drude 等条件后，根据
  原始排除表构造原子对。省去逐组/逐原子的重复距离判断。GPU 按原子序号
  生成列表，保留排除项和负号编码的 1–4 项。INTER 筛选使用稳定的块前缀和，
  保留原始原子对顺序。每个传输缓冲区最多 64 MiB，避免巨型 GPU 分配。
- 为保持 CHARMM 列表接口的一般语义，完整源列表仍存在。这里加速构表和
  保序筛选，没有让全局非键列表变成只含某次选择的列表。ENBOND 的能量和
  力计算未改动，避免改变浮点累加顺序。
- `pb_flags/mstep_cuda.cu`：GPU 并行计算四张网格的球内/壳层标记，整数 OR
  合并重叠原子的贡献，球内终态优先。只处理选中原子覆盖的包围盒，只回传
  一份压缩标记，CPU 一次性应用到后续步骤需要的主机网格。这样省去整张
  四网格往返拷贝与逐原子重复写网格。距离运算显式保留双精度舍入和原关联顺序。
- `pb/` 保存完整网格传输的首版实验，用于对照。最终候选使用 `pb_flags/`。
- 已有的 SOR、REEN 探针和边界求和继续使用 GPU。小规模网格写回、控制流程
  和原始 VDW 能量/力累加保留在 CPU。

不满足快速路径条件时使用原 CPU 例程。GPU 执行错误使当前原生计算失败，
不把部分结果当作完成结果。MSTEP 完成 GPU 运算及下载后才修改主机网格。

## 验证与资源约束

`pb_flags/test_mstep.py` 对照未经改写的 Fortran MAYER_MSTEP 循环，检查
112 组四网格逐位结果以及 6 组拒绝输入。完整野生型和突变体比较三分量电势
文件 SHA256，以及能量、网格尺寸、迭代次数和残差。

`vdw/test_pairs.py` 使用独立参考列表验证排序和排除项，含超过 64 MiB 的
跨块用例。`vdw/validate_native.py` 比较源列表、筛选列表、1–4 元数据、
192 项能量位模式和全部力的哈希；还覆盖短截断、共价分割、重叠/不完整选择、
KEEP、SHIFT、BYCUBES 和固定原子。实际速度使用无审计的生产库对照旧部署库。

所有原生测试取得 `runtime/energy.lock` 后串行执行。继续使用 30 GiB 可用内存
准入、20 GiB 进程地址上限、10 GiB 主机内存余量和 2 GiB GPU 余量。
编译为 nice 10，地址空间限制 8 GiB。没有提高生产 CPU 并发数。

`continue_scan.py` 在批次边界切换后端，保留前三个协议的已完成预测，冻结
WT 缓存与已准备的突变体结构。合并结果携带每行原始协议。`test_transition.py`
验证四来源合并、重复/身份错误拒绝、恢复时自身结果仍属于原计划，以及
实际冻结结构的复制和篡改拒绝。`verify_activation.py` 核验首个生产能量、
实际加载库、输入哈希与协议。

构建脚本使用本机已有的 CHARMM 源码和对象，编译/链接命令与输入哈希保存在
各 `build_manifest.json`。已部署目录和固定脚本应视为不可变；进一步修改应
新建构建目录和协议。

`deployment.json`、`transition.json` 与 `validation/production_activation.json`。

## 实测结果

冻结 WT / V130A 两组结果的中位数：

| 阶段 | 原版本（秒） | 新版本（秒） | 时间减少 |
|---|---:|---:|---:|
| VDW 完整进程 | 15.257 | 10.006 | 34.4% |
| PB 内部 MSTEP | 7.027 | 0.624 | 91.1% |
| PB 完整验证进程 | 52.021 | 45.518 | 12.5% |

MSTEP 已包含在 PB 总时间内，不能重复相加。VDW 与 PB 两进程合计减少约 17.5%。PB 验证额外写出三个完整电势文件，因此不应把该绝对时间直接当作生产每突变耗时；完整批次还包含结构准备和贡献计算。

生产切换已完成。首个 D160A 能量计算：VDW 10.01 秒、PB 41.02 秒，合计 51.03 秒。已通过进程映射核对实际加载库，并复核 80 个冻结 WT 缓存文件和 20 个捐赠坐标文件。此前 133 条完整预测保留；剩余 1,330 个突变由新协议继续计算。
